# content/ — 病例和督导标准

这里放 AI 来访者和 AI 督导用的内容。内容由聆镜团队的心理学同事写，我们（开发）不改临床内容。

我们把每个文件直接交给 AI 当「角色说明」或「评分标准」。所以：**写得越具体，AI 演得越像。** 不用写成论文，写成给一位扮演来访者的演员看的说明就行。

- 病例：`content/cases/<id>.md`，一个病例一个文件。
- 督导标准：`content/rubrics/cbt.md`，MVP 只有 CBT 一份。
- MVP 只要两个病例：抑郁、抑郁加焦虑。病例先写中文。
- 下面的模板直接复制，把 `<尖括号>` 换成内容，把示例删掉。拿不准的地方写「待定」，我们会来问。

> 只写虚构人物。不要用真实来访者的信息，哪怕改了名字。

---

## 1. 病例模板

文件名：`content/cases/<id>.md`，例如 `content/cases/cbt-depression-01.md`。

```markdown
---
id: cbt-depression-01            # 小写英文、数字、连字符。定了就不改。
school: cbt                      # MVP 只有 cbt
title:
  zh: <病例名，App 列表里显示，10 字以内。例：大学毕业后的低落>
  en: <English title, under 40 characters>
summary:
  zh: <一两句话，选病例前看到。不剧透核心信念。>
  en: <One or two sentences.>

# ↓ 以下都是可选，App 的病例卡片和病例简介页会显示。不填就不显示。下面的值是示例，换成你的病例。
# 这些都是选病例时、开始会谈前学员能看到的内容：不剧透核心信念，不剧透「不会轻易透露」的内容。
tags:                            # 主题标签，最多 3 个
  - zh: 抑郁
    en: Depression
difficulty: intro                # intro 入门 / medium 中等 / hard 较难
estimatedMinutes: 15             # 预计时长，分钟
clientIntro:                     # 「来访者」卡片：化名、年龄、身份、一句来访理由。2–3 句。
  zh: 小林，23 岁，毕业半年还没找到工作。家人劝来的，说「最近什么都不想做」。
  en: Xiao Lin, 23, still looking for work six months after graduating. Came because family insisted: "I don't feel like doing anything lately."
practiceFocus:                   # 「这次练什么」：1–3 条，每条一个技术或动作
  - zh: 建立关系
    en: Building rapport
  - zh: 识别自动思维
    en: Spotting automatic thoughts
contentNotes:                    # 内容提示。不填就用通用的：「可能涉及抑郁、焦虑和消极念头」
  zh: 这场会谈可能涉及失业、家庭冲突和消极念头。
  en: This session may touch on unemployment, family conflict and dark thoughts.
---

## 来访者基本情况
<化名、年龄、性别、职业/学业、家庭和居住情况、来咨询的途径（自己来 / 家人劝 / 学校转介）。
3–6 行。>

## 主诉
<来访者第一次见面会怎么说自己的问题，用来访者自己的话写一两句。
例：「最近什么都不想做，早上起不来，觉得自己挺没用的。」>

## 症状表现
<情绪、睡眠、食欲、精力、兴趣、注意力、社会功能。持续多久、什么时候开始、有没有触发事件。
写成要点。抑郁加焦虑的病例，请分开写抑郁的部分和焦虑的部分。>

## 认知模式和核心信念
- 自动思维：<2–4 条典型的，用来访者原话写。例：「我又搞砸了。」>
- 中间信念 / 规则：<例：「如果我不做到最好，别人就会看不起我。」>
- 核心信念：<例：「我是没用的。」>
- 常见认知歪曲：<例：灾难化、读心术、全或无。>
- 这些想法和情绪、行为怎么连在一起：<一个具体情境的例子：情境 → 想法 → 情绪 → 行为。>

## 说话风格
<语速、长短句、口头禅、会不会哭、会不会冷场、用词。
给 2–3 句示范台词。AI 会照这个口气说话。>

## 常见阻抗
<来访者在咨询里会怎样「卡住」。例：
- 被问到父母时转移话题；
- 对布置作业说「试过了，没用」；
- 咨询师太快给建议时，表面答应、其实不认同。
每条写一下：什么情况下出现，咨询师做对了以后会怎样缓和。>

## 会透露什么、不会轻易透露什么
- 一开始就会说：<主诉、表面的事件。>
- 建立信任后才说：<例：和父亲的关系、一次失败的经历。>
- 很难说出口、需要咨询师问到才说：<例：核心信念本身、羞耻的事。>
- 不知道的事：<来访者自己也没意识到的东西。AI 不会主动点破。>

## 风险等级与安全边界
- 风险等级：<低 / 中。MVP 不做高风险病例。>
- 有没有自伤或自杀念头：<没有 / 有消极念头但无计划，例：「有时候觉得活着挺累的」。>
- 被直接问到时怎么回答：<写清楚。例：「承认有过消极念头，否认计划和行动。」>
- 这个病例不会演到的地方：<例：不会描述具体的自伤方法；不会出现急性危机。>
- 参考 [`docs/safety.md`](../docs/safety.md)。

## 备注（可选）
<给督导用的背景：这个病例主要练什么技术（例：识别自动思维、苏格拉底式提问、行为激活）。>
```

**可选字段怎么填：**

- 这些字段是学员**开始会谈前**就能看到的。只写公开信息：来访者自己第一次见面会说的事。核心信念、中间信念、「建立信任后才说」的内容都不要写进来。
- `clientIntro` 像接案单上的一句话简介，不写诊断名，不写分析。
- `practiceFocus` 用督导标准里「要看的点」的说法，方便和督导报告对上。
- 英文可以先空着（写 `en: ""`），包括 title 和 summary。空着时，App 英文界面会显示中文。

**写完自查：**

- [ ] frontmatter 四项必填都填了（id、school、title.zh/en、summary.zh/en）。
- [ ] 可选字段里没有剧透核心信念或「不会轻易透露」的内容。
- [ ] 主诉、自动思维、示范台词用的是来访者的口吻。
- [ ] 「会透露 / 不会轻易透露」分了层。
- [ ] 风险等级和被问到自杀时的回答写清楚了。
- [ ] 人物是虚构的。

## 2. 督导标准模板

文件名：`content/rubrics/cbt.md`。AI 督导读完整场对话，按这份标准写报告。

```markdown
---
id: cbt
school: cbt
title:
  zh: CBT 会谈督导标准
  en: CBT session supervision rubric
---

## 这份标准适用于
<例：新手咨询师的 CBT 初次或早期会谈，单次 20–40 轮对话。>

## 要看的点
每一点写：看什么、做得好是什么样、做得不好是什么样。建议 6–10 点。

### 1. <例：建立关系和共情>
- 技能 id：<小写英文，例：rapport。报告的技能标签和进度统计用它，定了就不改。>
- 看什么：<例：是否回应来访者的情绪，是否先理解再干预。>
- 做得好：<例：用来访者的话复述感受；节奏不急。>
- 做得不好：<例：一上来就讲道理；忽略来访者哭了。>

### 2. <例：议程设置>
...

### 3. <例：识别自动思维>
...

### 4. <例：苏格拉底式提问 / 引导发现>
...

### 5. <例：认知概念化（情境—想法—情绪—行为）>
...

### 6. <例：心理教育的时机和方式>
...

### 7. <例：家庭作业 / 行为实验的布置>
...

### 8. <例：总结和反馈>
...

## 新手常见错误
<列出 5–10 条。每条一句话，最好附一句「错误示范」原话。例：
- 过早给建议：「你可以试试每天跑步。」
- 连续封闭式提问，像在问诊。
- 和来访者争论想法对不对。>

## 好的做法
<列出 5–10 条。每条附一句「示范」原话。例：
- 「你刚才说『我又搞砸了』，当时脑子里还闪过什么？」>

## 安全相关
<来访者表达消极念头时，咨询师至少应该做到什么。例：直接、平静地询问；不回避；不立即转移话题。
没做到的话，督导报告怎么写。参考 docs/safety.md。>

## 报告结构
AI 督导按这个结构写，MVP 固定三部分：

1. **做得好的地方**：2–4 条，每条引用咨询师的一句原话，说明好在哪。
2. **需要改进的地方**：2–4 条，每条引用咨询师的一句原话，说明问题，给一句可以换成的说法。
3. **下次练什么**：1–3 条，具体到一个技术或一个动作。

<语气：像一位温和、直接的督导。不打分。篇幅：中文 600–1000 字。>
```

**写完自查：**

- [ ] 每个「要看的点」都有做得好 / 做得不好的描述。
- [ ] 常见错误和好的做法都有原话示范。
- [ ] 报告三部分的要求写清楚了。
