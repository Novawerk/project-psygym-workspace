## D2 · 病例多几个公开字段

**要什么：** 病例卡片和简介页需要：主题标签、难度、预计时长、来访者的公开简介（化名、年龄、身份、来访理由）、这次练什么（1–3 个练习重点）、内容提示。

**改动：**

- `CaseSummary` 加可选字段（都是可选，旧 App 不受影响）：

  ```ts
  type CaseSummary = {
    id: string; school: "cbt"; title: LocalizedText; summary: LocalizedText;
    tags?: LocalizedText[];          // 例：抑郁、焦虑
    difficulty?: "intro" | "medium" | "hard";
    estimatedMinutes?: number;       // 例：15
    clientIntro?: LocalizedText;     // 化名、年龄、身份、来访理由，不剧透
    practiceFocus?: LocalizedText[]; // 这次练什么，1–3 条
    contentNotes?: LocalizedText;    // 内容提示，缺省用通用文案
  };
  ```

- 病例模板（`content/README.md`）frontmatter 加同名字段，聆镜团队来填。

| | 利 | 弊 |
|---|---|---|
| 加字段 | 简介页有内容可放；练习有方向；卡片能区分难度。 | 合同要改（两端同一个 PR）；聆镜要多填几项。 |
| 不加 | 不动合同。 | 简介页只能放标题和简介，和现在的病例列表差别不大，C2 就没必要做。 |

**建议：** 加。都是可选字段，向后兼容。可以和 D4 的合同改动放在同一个 PR 里。`clientIntro` 和 `practiceFocus` 写什么由聆镜定；「不剧透核心信念」这条写进模板。

## D3 · 在手机上保存练习记录

**要什么：** 练习记录、原话跳转、练习目标、技能进度，都要求把对话和报告存在手机上。

**现在：** 对话只在内存里，离开报告页就没了。代码注释、文案（「对话不会保存在任何地方」）、App README 都写了不存。CLAUDE.md 写的是「不存真实来访者数据」——模拟对话本身不是真实来访者数据，但用户可能违规输入真实信息。

**选项：**

| 选项 | 利 | 弊 |
|------|---|---|
| A. 不存（现状） | 最简单，隐私风险最小。 | 没有记录、没有进度；用户练完就忘，回访动力弱。练习记录、原话跳转、练习目标、进度都做不了。 |
| B. 存在本机，默认开，可关、可删 | 有记录和进度；数据只在用户手里，没有账号和云端。 | 手机丢了或被人看到，对话可能泄露；用户误输入的真实信息会留在手机上；要改文案、代码注释、备份设置。 |
| C. 存在本机，默认关，用户主动开 | 隐私最保守，又给想要的人留了功能。 | 大多数人不会去开，进度功能形同虚设。 |
| D. 存云端 + 账号 | 换手机不丢；能给真人督导看。 | 违背「服务端不存对话」；要账号、合规评估（PIPL 敏感个人信息、GDPR 第 9 条），工作量大。 |

**B 的附加要求（如果选 B）：**

- 第一次存之前告诉用户（会谈结束时一行字 + 设置里的开关）。
- 只存在 App 私有目录：Android 继续关 `allowBackup`；iOS 放在不进 iCloud 备份的目录。
- 设置里「删除所有练习记录」，单场也能删。
- 不加密的话，至少写进隐私说明；加密（系统钥匙串保存密钥）作为加分项，待定。
- `safety.md` 第 1 节、App 文案、App README 同步改。

**建议：** B。它是「让人回来再练」最核心的一项，进度、目标、原话跳转都靠它。同时写一条决策记录 `docs/decisions/` 并请聆镜看一眼：心理学同事对「练习对话留在学员手机上」有没有顾虑。

## D5 · 督导报告带技能标签

**要什么：** 报告每一条标一个技能（例：「苏格拉底式提问」），来自督导标准的要点。这是技能进度（M3）的数据来源。斯坦福的 CARE 研究里，练习加「带技能标签的反馈和替代说法」的组有进步，只练不反馈的组没有（来源见文末）。

**选项：**

| 选项 | 利 | 弊 |
|------|---|---|
| A. 在 Markdown 里约定格式（例：每条第一行 `` `技能：苏格拉底式提问` ``），App 解析 | 不改合同，只改提示词。 | 解析脆弱，模型偶尔不守格式。 |
| B. 报告结束后，流里多发一个结构化事件 `{"type":"report_meta","items":[{"section":"improve","skill":"socratic"}]}` | 稳定；Markdown 照常显示。 | 改合同；后端要多做一次结构化输出。 |

**建议：** 先 A，验证技能列表好不好用；进度页上线前换 B。技能列表由聆镜在督导标准里定（每个「要看的点」一个 id）。

## D6 · 「关于你」要不要发给后端

O4 问身份、CBT 熟悉程度、想练什么。

| 选项 | 利 | 弊 |
|------|---|---|
| A. 只存本机，只用来排推荐病例 | 隐私最简单，不改合同。 | 督导报告不会因人调整。 |
| B. 随督导请求发一个 `level` 字段 | 新手和有经验的人拿到不同深度的反馈。 | 改合同；隐私说明要写。 |

**建议：** 先 A。等聆镜告诉我们「不同经验的人，督导该怎么不同」，再做 B。

## D7 · 报告反馈发给我们

**要什么：** 报告底部「这份反馈有帮助吗？👍 / 👎 + 一句话」。这是我们改提示词最直接的依据。

| 选项 | 利 | 弊 |
|------|---|---|
| A. 只发评价和一句话，不带对话 | 数据少，隐私简单。 | 看不到上下文，不知道哪里不好。 |
| B. 用户勾选「附上这场对话」后才带对话 | 能复现问题。 | 服务端第一次存对话，要改 `safety.md` 和合同，要定保存期限。 |
| C. 不做，靠聆镜和测试人工反馈 | 不新增数据流。 | 公开测试后收不到大量反馈。 |

**建议：** 做 A，新开一个 `POST /feedback`（改合同）。B 等真的需要时再议。
