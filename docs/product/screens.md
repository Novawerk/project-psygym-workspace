每页按同一个结构写：**期、目的、内容（从上到下）、操作、状态、验收**。

全部在 10/17 demo 前实现。批次只排顺序：🟢 第 1 批 demo 必经；🔵 第 2 批 demo 前其余；🟠 第 3 批已定的新功能（D2、D3、D6、D7，见 [open-decisions.md](./open-decisions.md)）；🟣 等督导标准（D5）；⚪ 完整版。没有标记的内容跟所在页面的批次走。Onboarding 两页（O1、O2；第 3 批加 O4）在 [onboarding.md](./onboarding.md)。全部文案的中英对照在 [copy.md](./copy.md)。

## 通用

**视觉**

- 配色用 shadcn 默认的 neutral / zinc，简洁、黑白灰，不用品牌绿做主色。颜色只写在 `Theme.kt`。

  | 用途 | 浅色 | 深色 |
  |------|------|------|
  | 底色 | 白 `#FFFFFF` | zinc-950 `#09090B` |
  | 文字 | zinc-950 `#09090B` | zinc-50 `#FAFAFA` |
  | 次要文字 | zinc-500 `#71717A` | zinc-400 `#A1A1AA` |
  | 边框、分隔线 | zinc-200 `#E4E4E7` | zinc-800 `#27272A` |
  | 浅灰块（卡片、提示、来访者气泡） | zinc-100 `#F4F4F5` | zinc-900 `#18181B` |
  | 主按钮、咨询师气泡 | zinc-900 `#18181B` 底，白字 | zinc-50 `#FAFAFA` 底，zinc-900 字 |
  | 错误 | 只用于真正的错误，用主题的 error 色 | 同左 |
- 字号用 Material 3 默认层级；支持系统字号放大到 200% 不截断。
- 圆角：卡片 12，按钮和输入框 8，标签和分段控件全圆角。
- 图标：Material Symbols Rounded。插画只在 O1 和空状态出现，线条风格，灰阶。
- 不用红色表达「安全提醒」。红色只用于真正的错误。安全相关用浅灰块 + 盾牌图标，语气平和。

**布局**

- 主按钮在底部，拇指区，全宽。一页只有一个主按钮。
- 顶栏：左返回，中标题，右最多两个图标。
- 页面左右边距 20。

**无障碍**

- 所有图标按钮有读屏标签（例：「需要帮助」「设置」「结束会谈」）。
- 对比度 ≥ 4.5:1。
- 流式文字不要每个字都触发读屏；一段说完再读。

**错误**（统一用 ErrorCard：图标 + 一句话 + 一个按钮）

| 情况 | 文案（中） | 按钮 |
|------|-----------|------|
| 没网 | 连不上服务器，请检查网络后重试。 | 重试 |
| 邀请码不对 | 需要有效的邀请码。 | 去设置 |
| 太频繁 | 请求太频繁了，请稍等一分钟再试。 | 重试（倒计时结束后可点） |
| 模型不可用 | AI 暂时不可用，请过几分钟再试。 | 重试 |
| 病例不可用 | 这个病例暂时不可用。 | 换个病例（回 C1） |
| 会谈太长 | 这场会谈已经很长了。结束它，看看督导怎么说。 | 结束并查看督导 |
| 超时（30 秒没有任何数据） | 等了太久没有回应。 | 重试 |
| 未知 | 出了点问题，请重试。 | 重试 |

- 已经打的字不丢。
- 流到一半出错：已出来的半句保留，灰色显示，末尾标「（未完成）」，下方是 ErrorCard。重试时替换这半句。
- 错误码、英文原文、堆栈都不显示给用户。

## H1 · 首页

**目的：** 一眼知道这是什么，一步开始练习。

**批次：** 🟢

**内容**

1. 顶栏：左 Logo「聆镜 PSYGYM」。没有设置齿轮，设置在底栏「我的」里。
2. 问候：「今天练一场？」 副标题：「选一位来访者，开始一次 CBT 会谈。」
3. 主卡片（zinc-900 底，白字）：标题「开始练习」、一句「约 15 分钟 · 结束后有督导反馈」、小插画、按钮「选一位来访者」（→ C1）。
4. 「病例」小节：横向两张病例卡（同 C1 的卡片，缩小版：头像、「化名 · 病例名」、难度和时长），点卡片直接到 C2。右侧「全部 ›」到 C1。
5. 声明短版（小字，浅色容器，和 `safety.md` §5 一致）：「聆镜 PSYGYM 是给咨询师的练习工具。来访者由 AI 扮演，全部是虚构的。这不是心理治疗。」
6. 底部链接：「需要帮助？」
7. 底栏：练习（当前）/ 记录 / 我的。

**🟠 第 3 批（练习目标、最近练习）**

- 问候下方「你的练习目标」：上次报告里勾选的 1–3 个目标，例「用苏格拉底式提问代替给建议」。点开是那份报告。
- 「最近练习」：最近 2 场，显示病例名、日期、时长。点开到 M2。

**操作**

| 操作 | 去哪 |
|------|------|
| 开始练习 | C1 |
| 点病例卡 | C2 |
| 底栏「记录」/「我的」 | M1 / P1 |
| 需要帮助？ | X1 |

**状态**

- 病例还在加载：病例小节显示两张灰色骨架卡。
- 病例加载失败：病例小节换成 ErrorCard，主按钮仍然可点（进 C1 再试）。
- 演示数据（调试版）：顶栏 Logo 旁一个「演示数据」胶囊。

**验收：** A1、E1。

## C1 · 病例库

**目的：** 选一位来访者。

**批次：** 🟢；卡片标签 🔵，字段来自 D2，缺省时不显示。

**内容**

1. 顶栏：返回，标题「选择病例」。
2. 一行说明：「每位来访者都是虚构的，由 AI 扮演。」
3. 病例卡片列表，每张卡：
   - 头像位：一个抽象的圆形色块（不用真人照片，不用卡通脸），里面是化名的最后一个字（「小林」→「林」）。没有化名时用病例序号（一、二）。
   - 标题：「化名 · 病例名」（例：「小林 · 毕业后的低落」）。没有化名时只显示病例名。
   - 简介，最多 2 行。
   - 标签行：主题（抑郁 / 焦虑）· 难度（入门 / 中等 / 较难）· 约 15 分钟 · CBT。🟠 依赖 D2（已定，病例填了才有）；没有这些字段时，只显示「CBT」一个标签（来自现有的 `school`）。
4. 完整版：顶部加流派筛选（全部 / CBT / 精神分析 / 家庭治疗）。

**操作：** 点卡片 → C2。

**状态**

- 加载：3 张骨架卡。
- 空：插画 +「还没有病例。」
- 错误：ErrorCard + 重试。

**验收：** A2。

## C2 · 病例简介

**批次：** 🟢。替代练习前声明弹窗（D1 已定）。没有 D2 新字段时：「来访者」卡片显示病例简介，「这次练什么」不显示，内容提示用下面的通用文案。

**目的：** 进会谈前，让咨询师知道面对的是谁、这次练什么，并看到内容提示。

**内容**

1. 顶栏：返回，标题为空（滚动后显示病例名）。
2. 头部：头像色块、标题「化名 · 病例名」（同 C1）、标签行（同 C1，没有 D2 字段时只显示「CBT」）。标签行最前面加一个「初次会谈」标签（`brief_session_first`）。
3. 「来访者」卡片：化名、年龄、身份，一句来访理由。来自病例的公开简介（🟠 D2 `clientIntro`），不剧透核心信念。没有这个字段时，显示现有的病例简介 `summary`。
4. 「这次练什么」（🟠 D2 `practiceFocus`，没有时整块不显示）：上方一行小字「初次会谈的主要任务：做风险筛查，判断能不能承接这位来访者。」（`brief_session_first_note`）；列表的前两条固定是「风险筛查」「判断能不能承接」（病例模板要求）。1–3 个练习重点，带勾选样式的列表。例：「建立关系」「识别自动思维」。🟠 D3：用户自己的练习目标如果和这里有交集，高亮显示。
5. 「会谈设置」：初次会谈 · 建议 15–30 轮 · 约 15 分钟 · 你随时可以结束。（S-1，2026-10-11 定：MVP 的病例都是初次会谈。）
6. 内容提示（盾牌图标 + 浅色容器）：
   > 这场会谈可能涉及抑郁、焦虑和消极念头。来访者是虚构的。对话会交给第三方 AI 模型处理，我们的服务器不保存。
7. 主按钮「开始会谈」。下方一行链接「需要帮助？」。

**操作**

| 操作 | 去哪 |
|------|------|
| 开始会谈 | S1 |
| 需要帮助？ | X1 |
| 返回 | 上一页（C1 或 H1） |

**状态：** 简介数据来自 `GET /cases`，已经在 C1 拿到，不再请求。病例里没有「这次练什么」等新字段时，那一块不显示（向后兼容）。

**验收：** A3、E2、G6。

## S1 · 会谈

**目的：** 专心和来访者对话。

**批次：** 🟢

**内容**

1. 顶栏：
   - 左：返回（= 打开 S2）。
   - 中：来访者化名（`clientAlias`，没有时显示病例名）+ 下面一行小字「第 6 轮 · 08:32」（轮数 + 计时）。点一下可以隐藏计时。
   - 右：「需要帮助」盾牌图标（→ X1）、「结束」文字按钮（→ S2）。
2. 消息区：
   - 空状态：一张提示卡「你是咨询师。准备好了就先开口——可以像真实初次会谈一样开始。」
   - 咨询师气泡：右侧，zinc-900 底白字。
   - 来访者气泡：左侧，浅色；上方小字「来访者」。
   - 来访者正在回复：左侧三个点的动画；文字一出来就逐字显示。
3. 输入区：多行输入框（最多 5 行），占位「以咨询师身份说点什么…」，发送按钮。输入框上方一行小字，只在第一次会谈出现：「请不要输入真实来访者的信息。」
4. 接近上限（第 70 条消息起）：输入框上方一行提示「还能再说几轮。差不多可以结束了。」到 80 条时禁用输入，出现「结束并查看督导」按钮。
5. **来访者结束了会谈**（D4 已定，进 MVP）：来访者说完结束语后，后端在流里发 `session_end`。App：
   - 最后一条来访者气泡下方，居中一行系统提示「来访者结束了这次会谈」（灰色小字，两侧细线）。
   - 输入框和发送按钮隐藏，换成全宽主按钮「结束并查看督导」。
   - 顶栏「结束」按钮隐藏；「需要帮助」图标保留。
   - 按返回：直接打开 S2（「结束这次会谈？」那一种）。
   - 触发情况见 `safety.md` §3（第二次出现伤害性内容）；病例设定里也可能有自然结束。

**操作**

| 操作 | 结果 |
|------|------|
| 发送 | 消息上屏，来访者开始回复。回复中不能再发。 |
| 结束 / 返回 | 打开 S2 |
| 需要帮助 | 打开 X1（会谈保留，回来接着练） |
| 长按任意气泡 | 复制文字。长按来访者的气泡还多一项「举报这条回复」（🔵 第 2 批，D8 已定，见下文「举报」） |

**状态：** 流式中、出错（见通用错误）、切到后台再回来（会谈保留）。进程被系统杀掉后：🟢 第 1 批按移动端现在的做法回到病例列表；🔵 第 2 批改为回到首页并提示「上次的会谈没能保留」。

**验收：** A4–A6、B 节、D 节、E3。

## R1 · 督导报告

**目的：** 看懂这场哪里好、哪里改、下次练什么，然后再练。

**批次：**

- 🟢 第 1 批：头部信息（第 2 条）、生成中状态（第 3 条）、底部按钮（第 8 条）、离开确认，**以及第 4–6 条的分块和条目样式**。后端的报告格式已经上线（#57、#66），2026-10-11 我们定了按设计稿把卡片样式提前到第 1 批。
- 🟠：原话跳转、练习目标（D3）、反馈区块（D7）。🟣：技能标签（D5，等督导标准，格式见 [skill-tags.md](./skill-tags.md)）。

**按这个格式解析**（和后端 `apps/api/prompts/supervisor.md` 一致，以那份为准）：

- 三个二级标题，顺序固定：`## 做得好的地方`、`## 需要改进的地方`、`## 下次练什么`（英文 `## What went well`、`## What to improve`、`## What to practise next`）。
- 每条是一个 `- ` 开头的列表项，不编号，不用粗体小标题，一两句。
- **做得好：**`- 你说「原话」，好在……。`（英文 `- You said “…”, which …`）
- **需要改进：** 顺序固定为「问题 → 原话 → 换个说法」，都在同一个列表项里：`- 一句话说问题。你说：「原话」。可以换成：建议的说法`（英文 `- … You said: “…”. Try instead: …`）。替代说法**不加引号**。
- **风险筛查那条**排在「需要改进」第一，引用的是来访者：`来访者说：「原话」`（英文 `The client said: “…”`）。盾牌图标的判断见下面第 6 条。
- **下次练什么：**`- 一个技术或动作，一句话说怎么练。` 不引原话。
- 引号（中文「」、英文 “”）里只有逐字原话。
- 条数：做得好 1–2 条，需要改进 1–3 条，下次练什么 1–2 条；三部分都有，每部分至少 1 条。篇幅：中文 400–600 字，英文 250–400 词。
- 最后一行是 AI 声明，前面空一行。

App 解析每个列表项：把「你说：「…」」/「来访者说：「…」」那一段拿出来放进原话块（同一条里可能同时有「来访者说」和「你说」两段原话，按出现顺序各放一个原话块，分别标注说话人），把「可以换成：」后面的部分放进替代说法块，其余是说明文字。解析不出来时（格式不对），这一条按普通 Markdown 显示，不报错。

格式没改之前，App 不做解析，按普通 Markdown 显示。

页脚：「这份反馈由 AI 生成，仅供练习参考。」由后端写在报告末尾（验收 C7），App 不另加。

**内容**

1. 顶栏：标题「督导反馈」，右侧「需要帮助」图标。没有返回箭头（返回 = 回到首页，要确认）。
2. 头部：病例名 · 日期 · 时长 · 轮数。
3. 生成中：一张卡「督导正在读你们的对话…」+ 进度动画；报告逐段出现。
4. 报告三部分，每部分一个带图标的小标题：
   - **做得好的地方**（对勾）
   - **需要改进的地方**（箭头）
   - **下次练什么**（靶心）
5. 每一条的样式：
   - 说明文字（问题）在最上面。
   - 引用的原话放在一个浅底圆角块里，上方小字标注是谁说的（「你说」/「来访者说」）。
   - 「可以换成：」后面的替代说法单独一块，浅灰底，不加引号。
   - 🟣 D5（等督导标准）：每条右上角一个技能标签（例：「苏格拉底式提问」），来自督导标准的要点；原话可点，跳到对话里那一句（M2）。
6. 风险筛查那一条左侧多一个盾牌图标，不用红色。判断顺序：先看技能标签，是 `risk_screening` 就加；没有技能标签时（技能标签上线前），看是不是「需要改进」第一条、**只引了「来访者说」、没有「你说」**。任何一条都可以引来访者的话交代上下文，所以只看「有没有来访者说」会把普通的第一条误标成风险。见 [skill-tags.md](./skill-tags.md)。
7. 末尾一行：后端写的「这份反馈由 AI 生成，仅供练习参考。」（C7）。App 不另加文字。
8. 底部按钮区（生成完成后出现）：主按钮「再练这个病例」，次按钮「换个病例」。再下面文字链接「回到首页」。
9. 🟠 D3：「下次练什么」每条前面一个勾选框，「设为练习目标」。🟠 D7：底部加反馈区块（见下）。

**反馈区块（🟠 D7）**

报告生成完以后，在底部按钮上方：

1. 一行「这份反馈有帮助吗？」+ 两个按钮 👍 / 👎（读屏标签「有帮助」「没帮助」）。
2. 点了任意一个，下方展开一个单行输入框「想说一句吗？（可选）」（最多 500 字）+「发送」按钮，和一行小字「评价和这句话会转到我们内部的 Slack 频道，不收对话内容。」
3. 发送后整块换成「谢谢，我们收到了。」。不点发送、直接离开：只发评价。
4. 失败时不打扰：小字「没发出去」+「重试」。
5. 发给后端 `POST /feedback`（见 [`../api-contract.md`](../api-contract.md)）：评价、这一句话、病例 id、界面语言。后端转到我们内部的 Slack 频道，不进数据库。**不带对话，不带报告。**

**操作**

| 操作 | 去哪 |
|------|------|
| 再练这个病例 | C2（同一病例） |
| 换个病例 | C1 |
| 回到首页 | H1。弹确认：「离开后这份报告就没有了。」 |
| 需要帮助 | X1 |
| 长按报告 | 复制全文；长按一段 →「举报这段」（🔵 第 2 批，D8 已定） |

**状态：** 生成中离开要确认；生成失败见通用错误，重试会重新生成整份报告。

**验收：** A7–A9、C 节。

## 举报一条 AI 回复（🔵 第 2 批，D8 已定）

**目的：** 用户在 App 里举报冒犯或有问题的 AI 内容，不用离开 App。正式上架前必须有。demo 前不做。

**入口**

- 会谈页（S1）：长按来访者的一条回复 → 菜单「复制」「举报这条回复」。
- 报告页（R1）：长按一段 → 菜单「复制」「举报这段」。

**举报弹层**（底部弹层）

1. 标题「举报这条回复」。
2. 被举报的原文，放在浅灰块里，最多显示 4 行，可展开。上方小字「这段文字会发给我们」。
3. 原因（单选，必选）：冒犯或伤害性的内容 / 跳出了来访者的角色 / 给了危险或不当的建议 / 其他。
4. 一句话（可选，最多 500 字）：「想补充什么吗？」
5. 小字：「我们会收到这段文字、原因和你写的话，转到我们内部的 Slack 频道，不进数据库。不会发送整场对话。」

发给后端的接口见 [`../api-contract.md`](../api-contract.md)。
6. 主按钮「发送举报」（没选原因时不可点），次按钮「取消」。
7. 发送后弹层关闭，底部提示「谢谢，我们收到了。」。失败时弹层不关，显示「没发出去」+「重试」。

举报不影响会谈：会谈照常继续，被举报的回复不隐藏（第 2 批再看要不要加「隐藏这条」）。

## X1 · 需要帮助？（🟢）

**目的：** 给真的需要帮助的人一个出口。这一页任何时候都能打开，不需要网络。

**内容**

1. 顶栏：关闭（×）。
2. 标题：「如果你现在需要帮助」
3. 说明：
   > 这是一个练习工具，不能在危机中提供帮助。如果你或身边的人有危险，请马上联系当地急救电话或心理援助热线。
4. 一句：「如果你自己正在经历困难，请联系身边的专业人员，或拨打下面的心理援助热线。」
5. 「心理援助热线」：按地区分组（中国大陆 / 香港 / 台湾 / 德国 / 美国 / 英国）。手机系统地区那一组排第一、默认展开；其他地区折叠在「其他地区」下面，点开看。每条：名称、说明（服务时间等）、号码按钮（点击打开拨号界面）；每组末尾是紧急电话按钮（如「急救 120」）。系统地区不在表里时，先显示「不在这些地区：请拨打当地的急救电话。」号码表和来源见 [safety.md](../safety.md) §5，2026-10-17 核对。
6. 小字：「号码核对于 2026 年 10 月，每半年重新核对一次。」
7. 底部一行：「如果是练习让你感到不舒服，可以停下来，和你的督导或信任的人聊聊。」

**验收：** E3。

## P3 · 隐私说明（🟢）

用问答写，一问一句话为主。

| 问 | 答 |
|----|----|
| 对话去了哪里？ | 你发的每一句，连同之前的对话，发到我们的服务器，再转给第三方 AI 模型服务（目前是 DeepSeek / Anthropic，以实际配置为准）生成回复。 |
| 你们存吗？ | 我们的服务器不保存对话，也不在日志里记录对话内容。 |
| AI 模型服务存吗？ | 按它们自己的政策处理。我们列出用的是哪家、链接到它们的政策。（具体链接待定） |
| 手机上存吗？ | 存。每场练习的对话和报告存在这台手机上 App 自己的空间里，未加密，不上传，不进云备份。可以在「我的」里关掉保存或全部删除，也可以在练习记录里删除单场。卸载 App 就全部删除。 |
| 举报一条回复时，你们收到什么？ | 被举报的那一段文字、你选的原因和你写的话，还有病例编号和界面语言，转到我们内部的 Slack 频道（第三方服务），不进数据库。不会发送整场对话。（举报功能在第 2 批上线。） |
| 你们收到我的评价吗？ | 只有你在报告页点了 👍 / 👎 时才发。评价和你写的那句话会转到我们内部的 Slack 频道（第三方服务），不进数据库；还会带上病例编号和界面语言。那句话最多 500 字。不收对话内容。 |
| 你们收集什么？ | 邀请码：每次请求会发给我们的服务器，用来校验和限流，服务器不保存邀请码。你选的界面语言：每次请求也会带上，用来决定来访者和报告用哪种语言。没有账号，不收集姓名、手机号、位置。 |
| 我们统计什么？ | 我们在服务器上按天统计匿名的数字，按病例和界面语言分开：开始了几场会谈、来访者主动结束了几场、写了几份报告、每场几轮、一场多长、出了几次错、收到几次 👍/👎 和举报。只有数字，不含对话，不含任何能认出你的信息。 |
| 我能输入真实来访者的信息吗？ | 不能。请只把它当练习。 |

> 隐私和合规（中国 PIPL、欧盟 GDPR）在正式公开发布前需要专业意见。这一页的措辞是产品草稿，待定。
