# 督导报告的技能标签（草案）

**状态：等督导标准。** 我们定了 D5：先在 Markdown 里约定格式，不改合同。技能 id 来自聆镜的 CBT 督导标准（`content/rubrics/cbt.md` 里每个「要看的点」的「技能 id」）。督导标准到了，我们再把下面的格式写进督导提示词，App 再做解析。

## 格式

「做得好的地方」和「需要改进的地方」里，每一条的**第一行**单独写技能：

```markdown
## 需要改进的地方

技能：risk_screening

> 来访者说：「觉得起来也没什么意义。」

（说明）

可以换成：「……」
```

- 第一行固定写 `技能：` + 技能 id（英文报告写 `Skill: ` + 技能 id）。id 是英文小写，和督导标准里的一字不差。
- 一条只标一个技能。拿不准时标最主要的那个。
- 「下次练什么」不标技能。
- 「没有做风险筛查」那条固定标 `risk_screening`，App 据此加盾牌图标（这一个 id 我们先定下，督导标准里请用同一个）。
- 督导标准里没有的 id，App 不显示标签，也不计入进度。

## App 怎么用

- 报告页：每条右上角显示技能名（中英文名来自督导标准的标题，App 内置一份 id → 名称表）。`技能：` 这一行本身不显示。
- 技能进度（M3）：按 id 统计最近几场「做得好」「需要改进」各几次。依赖本机练习记录（D3，见 [`../decisions/0005-local-practice-history.md`](../decisions/0005-local-practice-history.md)）。
- 格式不对（没有 `技能：` 行、id 不认识）：照常按普通 Markdown 显示，不报错。
