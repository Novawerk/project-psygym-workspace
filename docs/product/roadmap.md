# 路线图和实现顺序

完整设计在 10/18 demo 前实现。下面的批次只排**先做什么、后做什么**：先做 demo 一定会走到的路径，再做其余；要等决策的，决策定了再做。页面编号见 [information-architecture.md](./information-architecture.md)。

| 标记 | 批次 | 什么时候 |
|------|------|----------|
| 🟢 | 第 1 批：demo 必经路径 | 最先做，demo 前必须完成 |
| 🔵 | 第 2 批：demo 前其余 | 第 1 批完成后，demo 前尽量完成 |
| 🟠 | 第 3 批：已定的新功能 | 第 2 批之后；demo 前做不完的放到 demo 后 |
| 🟣 | 等内容 | 等聆镜的督导标准到了再做 |
| ⚪ | 完整版 | 圣诞前 |

## 🟢 第 1 批：demo 必经路径

**目标：聆镜团队第一次打开 App，从引导走到督导报告，每一步都顺，每一步都安全。**

| 功能 | 页面 | 验收 |
|------|------|------|
| Onboarding 三页：这是什么、先说清楚（勾选同意）、准备开始（语言 + 邀请码） | O1–O3 | G1–G5 |
| 首页改版：开始练习主卡片、病例卡、声明短版、需要帮助链接 | H1 | A1、E1 |
| 病例库：说明一行、卡片（只显示「CBT」标签，D2 定了再加其他标签） | C1 | A2 |
| 病例简介页，替代练习前声明弹窗 | C2 | A3、E2、G6 |
| 会谈页补齐：需要帮助图标、轮数和计时、真实信息提示、上限提示、错误处理 | S1 | A4–A6、D 节、E3 |
| 来访者结束会谈：收到 `session_end` 后锁住输入（D4 已定） | S1 | B8 |
| 结束会谈弹层：三种情况的文案 | S2 | A7、C6 |
| 报告页：头部信息、生成中状态、普通 Markdown 正文、再练这个病例 / 换个病例 / 回到首页 | R1 | A7–A9、C 节 |
| 需要帮助？页 | X1 | E3、G8 |
| 底栏：练习 / 记录 / 我的（只在三个顶层页） | H1、M1、P1 | G10 |
| 「我的」：设置（语言、邀请码）、练习记录开关和全部删除、需要帮助、隐私说明、重新看引导 | P1 | A10、A1a、G11 |
| 本机练习记录：每场存在手机上（D3），第一次保存前告知，不进云备份 | S2、R1 | G11 |
| 练习记录列表、单场回看、单场删除 | M1、M2 | G11 |
| 隐私说明 | P3 | G7 |

C1、C2、S1 在病例没有 D2 新字段时也能用：显示标题、简介和通用内容提示，标签行只显示「CBT」，会谈页顶栏显示病例标题。

## 不在计划里

账号和云同步、排行榜和徽章、总分、给来访者（患者）用、真实来访者的录音或逐字稿上传。要做其中任何一项，先回到 [principles.md](./principles.md) 和 [`../safety.md`](../safety.md)，写决策记录。
